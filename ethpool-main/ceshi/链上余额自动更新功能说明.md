## 一、管理后台用户列表 - 链上钱包余额

### 功能位置
管理后台 → 用户管理 → 用户列表 → "查余额"按钮

### 修复内容

#### 1. 批量查询链上余额
- **API升级**：从 `/api/admin/query-balance` 改为 `/api/user/chain-balance`
- **数据来源**：直接查询以太坊主网链上真实USDT余额
- **查询地址**：优先使用授权地址，如无则使用注册地址

#### 2. 查询逻辑优化
```typescript
// 查询顺序
1. 遍历所有有钱包地址的用户
2. 确定查询地址（授权地址 > 注册地址）
3. 调用链上余额查询API
4. 更新余额显示
5. 添加800ms延迟避免RPC节点过载
```

#### 3. 使用方法

**步骤1：点击"查余额"按钮**
- 位置：用户列表顶部工具栏
- 图标：眼睛图标
- 状态：按钮会显示"查询中..."

**步骤2：等待批量查询完成**
- 每个用户查询间隔：800ms
- 实时显示查询进度
- 链上钱包余额列显示加载动画

**步骤3：查看结果**
- 成功：显示8位小数的USDT余额
- 失败：显示"查询失败"或"网络错误"
- 完成弹窗：显示成功/失败统计

#### 4. 显示效果

| 状态 | 显示内容 | 颜色 |
|------|---------|------|
| 查询中 | 旋转图标 + "查询中..." | 默认 |
| 成功 | 123.45678900 | 紫色 |
| 失败 | 查询失败 | 紫色 |
| 错误 | 网络错误 | 紫色 |

#### 5. 技术细节

**API调用示例：**
```javascript
GET /api/user/chain-balance?address=0x1234...5678

响应：
{
  "success": true,
  "data": {
    "address": "0x1234...5678",
    "usdtBalance": "123.456789",
    "blockNumber": 18234567,
    "timestamp": "2025-10-09T12:00:00Z"
  }
}
```

**RPC节点配置：**
- 使用多个公共RPC节点轮询
- 自动切换失败节点
- 提高查询成功率

## 二、代理后台用户列表 - 总余额

### 功能位置
代理后台 → 推广成员管理 → "刷新余额"按钮 / "开启自动刷新"按钮

### 新增功能

#### 1. 手动刷新余额
**原功能：**
- 按钮文字：刷新

**新功能：**
- 按钮文字：刷新余额
- 加载状态：显示旋转图标 + "刷新中..."
- 禁用状态：刷新时按钮不可点击
- 完成提示：自动更新列表和刷新时间

#### 2. 自动刷新功能（新增）

**开启方式：**
- 点击"开启自动刷新"按钮
- 按钮变为绿色，显示"已开启自动刷新"

**刷新间隔：**
- 30秒自动刷新一次
- 自动从数据库获取最新余额数据

**显示信息：**
- 上次刷新时间：HH:MM:SS格式
- 实时更新刷新时间

**关闭方式：**
- 再次点击按钮
- 按钮变为灰色，显示"开启自动刷新"

#### 3. 使用方法

**方法1：手动刷新**
1. 点击"刷新余额"按钮
2. 等待数据加载（显示"刷新中..."）
3. 查看更新后的余额数据

**方法2：自动刷新**
1. 点击"开启自动刷新"按钮
2. 系统每30秒自动刷新一次
3. 查看上次刷新时间
4. 需要时可点击按钮关闭自动刷新

#### 4. 显示效果

**按钮状态：**

| 状态 | 按钮颜色 | 按钮文字 | 说明 |
|------|---------|---------|------|
| 未开启 | 灰色 | 开启自动刷新 | 手动刷新模式 |
| 已开启 | 绿色 | 已开启自动刷新 | 30秒自动刷新 |
| 刷新中 | 蓝色 | 刷新中... | 禁用状态 |

**刷新时间显示：**
```
上次刷新: 14:23:45
```

#### 5. 余额数据说明

**余额列显示：**
- 字段：`member.cash`（从数据库查询）
- 格式：¥123.45（保留2位小数）
- 来源：`nh_member_new` 表的实时数据

**质押列显示：**
- 字段：`member.usdt`
- 格式：123.45 USDT（保留2位小数）
- 来源：`nh_member_new` 表的实时数据

## 四、常见问题

### Q1: 管理后台批量查询很慢？
**A:** 正常现象，因为需要查询真实链上数据：
- 每个用户间隔800ms
- 10个用户约需8秒
- 50个用户约需40秒
- 建议在用户较少时查询或分批查询

### Q2: 某些用户显示"查询失败"？
**A:** 可能原因：
1. 钱包地址无效
2. RPC节点临时不可用
3. 网络连接问题
- 解决：再次点击"查余额"按钮重试

### Q3: 代理后台自动刷新会影响性能吗？
**A:** 不会：
- 仅查询数据库，速度很快
- 30秒间隔足够长
- 只在当前页面激活时刷新
- 关闭页面自动停止

### Q4: 链上余额和平台余额不一致？
**A:** 这是正常的：
- 链上余额：用户钱包里的真实USDT
- 平台余额：平台记录的可提现金额
- 已兑换余额：已质押到平台的USDT
- 三者关系：链上余额 ≥ 平台余额 + 已兑换余额

### Q5: 如何验证链上余额准确性？
**A:** 三种验证方式：
1. 访问 Etherscan: `https://etherscan.io/address/用户地址`
2. 查看USDT合约地址: `0xdAC17F958D2ee523a2206206994597C13D831ec7`
3. 对比MetaMask等钱包显示的余额

## 七、技术架构

### 管理后台链上查询流程
```
用户点击"查余额"
    ↓
前端: batchQueryBalances()
    ↓
遍历所有用户
    ↓
GET /api/user/chain-balance?address={addr}
    ↓
API: ethers.js查询以太坊主网
    ↓
USDT合约: balanceOf(address)
    ↓
返回余额（6位小数）
    ↓
前端: 更新balanceStates状态
    ↓
UI: 显示余额（8位小数）
```

### 代理后台刷新流程
```
用户点击"刷新余额" / 30秒定时器
    ↓
前端: fetchMembers()
    ↓
GET /api/agent/members?page=1&limit=20&level=all
    ↓
API: Supabase查询nh_member_new表
    ↓
查询字段: cash, usdt, status等
    ↓
返回成员列表数据
    ↓
前端: 更新members状态
    ↓
UI: 显示最新余额
    ↓
更新刷新时间: lastRefreshTime
```
