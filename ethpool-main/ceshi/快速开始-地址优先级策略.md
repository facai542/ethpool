### 步骤 3: 设置定时任务（2 分钟）

#### 选项 A: 使用 cron-job.org（免费，推荐）✅

1. 访问 https://cron-job.org/en/signup.html
2. 注册账户（免费）
3. 创建新任务：
   - **Title**: `Tokenview 地址清理`
   - **URL**: `https://ethmax.vercel.app/api/cron/cleanup-tokenview`
   - **Schedule**: `0 2 * * *`（每天凌晨 2:00 UTC）
   - **Request Method**: `POST`
   - **Custom Headers**:
     ```
     Authorization: Bearer 你的CRON_SECRET
     ```
4. 保存并启用

#### 选项 B: 使用 GitHub Actions（免费）✅

创建文件 `.github/workflows/cleanup-tokenview.yml`:
```yaml
name: Cleanup Tokenview Addresses
on:
  schedule:
    - cron: '0 2 * * *'  # 每天 2:00 UTC
  workflow_dispatch:  # 允许手动触发

jobs:
  cleanup:
    runs-on: ubuntu-latest
    steps:
      - name: Trigger Cleanup
        run: |
          curl -X POST https://ethmax.vercel.app/api/cron/cleanup-tokenview \
            -H "Authorization: Bearer ${{ secrets.CRON_SECRET }}"
```

然后在 GitHub 仓库设置中添加 Secret：
- Name: `CRON_SECRET`
- Value: 你的 CRON_SECRET

## ⚠️ **常见问题**

### Q1: 清理任务没有执行？

**检查**:
1. cron-job.org 任务是否启用
2. CRON_SECRET 是否配置正确
3. Vercel 日志是否有错误

**解决**:
```bash
# 手动触发测试
curl -X POST https://ethmax.vercel.app/api/cron/cleanup-tokenview \
  -H "Authorization: Bearer 你的CRON_SECRET" -v
```

### Q2: 新用户授权后没有添加到 Tokenview？

**检查**:
1. Vercel 环境变量 `TOKENVIEW_API_KEY` 是否配置
2. 查看授权日志：搜索 "智能添加地址"
3. Tokenview 是否已达到上限（10 个）

**解决**:
```bash
# 查看当前监听地址数量
node ceshi/check-tokenview-addresses.js

# 如果已满 10 个，手动清理
node ceshi/manual-cleanup-tokenview.js
```

### Q3: 定时任务返回 401 Unauthorized？

**原因**: CRON_SECRET 不匹配

**解决**:
1. 检查 Vercel 环境变量中的 `CRON_SECRET`
2. 确认 cron-job.org 中的 `Authorization` header
3. 确保格式正确：`Bearer 你的密码`
