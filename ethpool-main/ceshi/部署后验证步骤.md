## 故障排查路径

### 如果验证1失败（API返回404）

**原因**：API 路由未部署

**解决**：
1. 检查 Vercel 构建日志
2. 确认 `src/app/api/moralis/webhook/route.ts` 文件存在
3. 重新部署

### 如果验证2失败（Moralis测试没收到）

**原因**：Webhook 无法访问或返回错误

**检查**：
1. Vercel 日志中是否有 POST /api/moralis/webhook
2. Moralis Dashboard 中查看 Webhook 错误
3. 确认 Webhook URL 配置正确

**解决**：
```javascript
// 更新 Webhook URL
await Moralis.Streams.update({
  id: 'ddc148ad-ca5a-4e0e-930b-a4769022c670',
  webhookUrl: '实际的Vercel域名/api/moralis/webhook'
})
```

### 如果验证3失败（数据库测试没通知）

**原因**：数据库触发器或 Telegram 通知有问题

**检查**：
```sql
-- 检查触发器状态
SELECT * FROM information_schema.triggers
WHERE trigger_name = 'trigger_wallet_transaction_notification';

-- 检查待发送通知
SELECT * FROM telegram_notification_queue
WHERE is_sent = false;
```

### 如果验证4失败（真实交易没通知）

**可能原因**：
1. **交易未确认**：需要等更久（2-5分钟）
2. **Moralis未推送**：检查 Moralis Dashboard Activity 日志
3. **Webhook失败**：检查 Vercel 日志

**深入检查**：
1. Moralis Dashboard → Stream → Activity → 查看是否有你的交易
2. Vercel → Logs → Functions → /api/moralis/webhook → 查看是否收到请求
3. Supabase → SQL Editor → 查询 wallet_transactions 表

## 系统架构（最终版）

```
用户授权成功
    ↓
地址添加到 Moralis Stream（45个）
    ↓
【等待真实交易】
    ↓
链上 USDT 转入/转出
    ↓
以太坊区块确认（15秒 = 1区块）
    ↓
Moralis Stream 检测到交易
    ↓
Moralis 推送 Webhook
POST https://ethmax.vercel.app/api/moralis/webhook
    ↓
Webhook API 解析事件
    ↓
检查是否为监听地址
    ↓
写入 wallet_transactions 表
    ↓
数据库触发器自动执行
    ↓
查询 nh_member_new（用户信息和最新备注）
    ↓
查询 nh_agents（代理信息）
    ↓
构建 Telegram 消息（使用最新数据）
    ↓
插入 telegram_notification_queue
    ↓
telegram-notifier v23 发送
    ↓
Telegram 群组收到通知
```

## 消息中显示的数据来源

| 字段 | 数据来源 | 实时性 |
|------|---------|--------|
| 钱包余额 | 交易金额（wallet_transactions.amount） | 交易时 |
| 顶层代理 | nh_agents.agent_name（触发器查询） | 实时 ✅ |
| 代理昵称 | nh_agents.agent_code（触发器查询） | 实时 ✅ |
| 用户编号 | 计算（按授权时间） | 实时 ✅ |
| 用户备注 | nh_member_new.telegram_user_id（触发器查询） | 实时 ✅ |
| 是否活动 | nh_member_new.is_active（触发器查询） | 实时 ✅ |
| 用户钱包 | wallet_transactions.user_address | 交易时 |
| 订单金额 | wallet_transactions.amount | 交易时 |
| 授权时间 | wallet_transactions.timestamp | 交易时 |
| 交易对象 | wallet_transactions.from/to_address | 交易时 |

**关键**：
- 所有用户和代理信息都是**触发器实时查询的**
- 管理后台修改备注后，**下次交易通知会显示新备注**
- 不是缓存数据，完全实时
